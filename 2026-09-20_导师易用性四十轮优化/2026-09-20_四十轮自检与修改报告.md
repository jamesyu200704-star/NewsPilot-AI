# NewsPilot 四十轮自检与修改报告

## 目标

让第一次使用 NewsPilot 的导师无需理解模型、RAG 或技术配置，只提供一句采访主题或一篇已有稿件，就能得到可直接使用、对象不串、事实不乱、失败说明清楚的结果。

## 四十轮结果

| 轮次 | 自检发现 | 实际修改 | 验证证据 |
|---|---|---|---|
| 1 | 选择任务后还要再点输入框 | 选择采访准备或新闻编辑后自动聚焦输入框 | 组件测试“选择任务后直接聚焦输入框” |
| 2 | 点击采访示例后焦点停留在按钮 | 示例写入后焦点返回输入框，可直接补充并按 Enter | 组件测试“点击采访示例后把焦点送回输入框” |
| 3 | 生成时仍能切换任务，容易让请求和页面状态错位 | 生成期间锁定任务入口、示例、编辑方式和重新选择 | 组件测试“生成期间锁定任务入口并允许取消” |
| 4 | 本地模型慢时用户只能等待 | 增加“取消生成”，取消后保留原输入 | 取消路径组件测试 |
| 5 | 生成时禁用输入框会导致文字无法选择复制 | 改为只读，保留选择和复制能力 | 组件测试“生成期间输入内容仍可选择复制但不能继续改写” |
| 6 | 等待状态只显示按钮转圈，不清楚内容是否保留 | 增加本地处理说明和取消提示 | 同一生成状态测试及浏览器检查 |
| 7 | 所有失败都显示同一句话，用户不知道下一步做什么 | 区分取消、超时、繁忙、输入错误、服务离线和普通失败 | `编辑服务.test.ts` 失败类型测试 |
| 8 | 快速双击或连续按 Enter 可能重复请求 | 增加请求锁，重复提交只发送一次 | 组件测试“快速重复提交时只发送一次请求” |
| 9 | 长稿没有前端边界，超过服务端容量后才失败 | 输入上限改为三万字，接近上限时显示剩余字数 | 组件测试“三万字并提示剩余字数” |
| 10 | 服务端原 32KB JSON 限制接不住三万中文字符 | 请求体限制提高到 128KB | API 测试“三万个中文字符的长稿”返回 200 |
| 11 | 采访结果按钮写“修改原稿”，概念错误 | 采访改为“修改主题”，新闻编辑保留“修改原稿” | 组件测试“采访结果返回输入时使用修改主题” |
| 12 | 复制新闻成稿时可能夹带工作台栏目文字 | 新闻编辑只复制成稿正文 | 组件测试“复制新闻成稿时不夹带工作台栏目名称” |
| 13 | 完整采访复制缺少对象、提问目的和追问 | 完整复制加入采访重点、对象、问题、目的、追问、资料依据和提醒 | 完整采访复制组件测试 |
| 14 | 用户不能单独带走某一道采访题 | 每题增加“复制这一题”及成功反馈 | 单题复制组件测试 |
| 15 | 多分组问题各自从 1 开始，现场使用容易混乱 | 页面和复制文本都使用连续编号 | 连续编号两项组件测试 |
| 16 | 结果页看不出生成规模和修改幅度 | 采访显示对象数、问题数；编辑显示原稿与成稿字数 | 两项结果统计组件测试 |
| 17 | 搜索失败会暴露 Bing、provider、timeout 等技术词 | 改成普通用户能理解的公开资料说明 | 组件测试“搜索失败时不暴露供应商文案” |
| 18 | “待核实、暂无、无待核实项”形成无意义栏目 | 过滤没有信息量的占位词，不显示空核实栏目 | 组件测试“新闻编辑结果不显示占位词” |
| 19 | 输入帮助和错误没有完整关联输入框 | 使用 `aria-describedby`、`aria-invalid` 和错误状态 | 无障碍组件测试 |
| 20 | 手机上操作按钮和单题复制容易挤压 | 优化 390px 下任务入口、结果按钮、问题卡片和复制按钮布局 | 390×844 浏览器检查，无横向溢出 |
| 21 | 新闻润色可能遗漏日期、时间、数字或引语 | 提示词逐项要求保留，Provider 对数字、日期、时间和比分执行事实保护 | Ollama Provider 事实保护测试；真实 N01、N04 通过 |
| 22 | 新闻评论可能把“部分学生”改成具体群体 | 禁止把模糊主体具体化，禁止用叙事句补写新事件 | 评论事实约束测试 |
| 23 | 评论连续失败时直接返回错误或不安全初稿 | 改为仅依据原稿生成保守评论 | 评论降级测试；真实 N03 通过 |
| 24 | 润色失败时把模型错误伪装成原稿“待核实” | 失败时保留原稿，不生成虚假的核实项 | Provider 降级测试验证 `verificationNeeded` 为空 |
| 25 | 校医院、门诊、就诊主题会被分到普通校园事件 | 统一识别为“公共服务” | 编辑核心测试“校医院延长夜间门诊” |
| 26 | 医疗主题会给出泛化“学生代表、事件相关人员” | 改为“就诊学生代表、校医院负责人” | 核心测试与真实 I02 通过 |
| 27 | 模型偶尔只返回补充对象，没有主要对象 | 自动选择受影响者为主要采访对象 | 核心测试“公共服务只返回学生对象时自动补足” |
| 28 | 公共服务缺少执行方，无法询问原因和安排 | 自动补足服务运营或具体负责人 | 同一核心测试覆盖执行方 |
| 29 | 过滤坏问题后可能只剩一两题 | 按事件类型补足到至少 6 题，上限 8 题 | 核心测试及10个真实案例均为 6—8 题 |
| 30 | “调整原因、开始实施、收集反馈”可能问给学生 | 执行与规则问题自动交给执行方，体验问题交给受影响者 | 多项对象分配测试 |
| 31 | 修正采访对象后，问题、目的或追问仍残留旧称谓 | 对问题、目的和追问同步替换旧对象称谓 | 核心测试“同步清理错误称谓”；音乐节浏览器复验 |
| 32 | 采访重点统一套“人生经历”模板 | 按人物赛事、政策、突发、公共服务等事件类型生成重点 | 核心测试“采访重点根据事件类型生成” |
| 33 | 不同主题之间可能串入比赛、食堂、财报等模板 | 加强领域词、凭空姓名、无资料事件类型和无关对象过滤 | 跨主题核心测试；真实10例无串题 |
| 34 | 结构修改验证把语气词“已”当成硬事实，造成误报 | 验证改为检查日期、时间、地点和周期等事实锚点，并输出具体缺失项 | N02 从误报改为真实事实检查，完整通过 |
| 35 | 首屏标题“从采访问题到新闻成稿”暗示两个功能是前后流程 | 改为并列标题“采访准备与新闻编辑” | 组件测试与浏览器首页快照 |
| 36 | 单题复制失败时按钮仍显示“这一题已复制” | 只有剪贴板写入成功才显示成功；失败提示手动复制 | 组件测试“复制单题失败时不显示已复制” |
| 37 | `notes` 为空时仍显示空白“编辑说明” | 说明和回看栏目都为空时整块隐藏 | 组件测试“结果没有编辑说明时不显示空栏目” |
| 38 | 音乐节暴雨取消被泛化为“学生代表、事件相关人员”，问题还讨论活动内容 | 对象改为“原定参加音乐节的学生、音乐节主办方”；删除偏题的“应该举行、内容、安全”问题；取消决定、通知、费用、延期问主办方，实际影响问学生 | 核心测试、真实 I03、三轮浏览器复验 |
| 39 | 团队夺冠只给“赛事相关人员”，导师不知道具体找谁 | 团队赛事补充对象具体化为“主要人物的队友或教练” | 核心测试与真实 I06 通过 |
| 40 | 润色或结构修改触发事实保护后，结果页看起来仍像已完成成稿 | API 返回普通用户可读的降级说明；结果页用醒目提示说明正文已保留为原稿 | Provider 测试与组件测试“事实检查降级时明确说明” |

## 最终验证

- 本地千问真实调用：10/10 通过。
  - 采访 6 例：夜间班车、校医院、音乐节取消、鹅腿阿姨、生成式 AI 写作规定、篮球夺冠。
  - 新闻编辑 4 例：日期和引语润色、班车结构修改、图书馆评论、比分和引语润色。
  - 检查内容：本地千问、主题理解、对象数量、问题数量、对象存在、单一问题、事实保留、数字不新增、跨主题污染。
- 前端自动测试：13 个测试文件，73/73 通过。
- 当前双功能编辑路径服务端测试：71/71 通过。
- 生产构建：TypeScript、服务端编译和 Vite 构建通过。
- 浏览器实测：Google Chrome 1366×768、390×844；手机视口 `scrollWidth` 与 `clientWidth` 均为 375，无横向溢出；控制台 0 个错误。
- 全量旧服务端套件：189/191 通过。两个失败属于旧 Vercel 搜索 Provider 期望和旧学生报道20题评估，不在本轮双功能 MVP 修改路径中，本轮没有为制造全绿而改动旧模块。

## 当前边界

- 采访准备只生成采访对象和问题，不代替真实采访，也不把公开资料当成受访者回答。
- 新闻编辑只处理用户粘贴的材料，不补写材料外的新闻事实。
- 本地模型初稿未通过事实保护时，润色或结构修改会保留原稿并明确提示；评论会改用仅依据原稿的保守版本。
- 实时搜索不可用时仍能生成提纲，但页面会说明暂未找到可用公开资料。
