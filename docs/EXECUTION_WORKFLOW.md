# 报道执行工作流

P2 把 `StudentReportingPlan` 继续推进为可落地的报道执行项目：

```text
课程/刊发任务
  → 截止期倒排
  → 采访对象与人工联系
  → 分信源采访提纲
  → 同意与归因确认
  → 现场笔记 / 人工或本地转写
  → 候选主张、引语与线索（人工确认）
  → 证据缺口与追踪任务
  → 证据支撑的报道提纲
  → 作业阻断检查
  → 脱敏 DOCX / Markdown / CSV / ZIP
```

## 九个视图

概览、任务、采访对象、采访提纲、采访记录、证据、报道结构、作业自查、导出是九个独立视图。概览只显示今日三件事、阻塞、倒计时、未完成关键采访和未核实关键主张。

## 状态原则

- 自动化只能生成计划、候选项和规则提示。
- 联系动作由用户在站外完成，NewsPilot 只记录。
- 采访完成必须有使用同意、归因确认、已复核笔记、未回答项和采访后复盘。
- 受访者陈述保留归因和未核实状态，不能自动成为事实。
- 任何提交阻断项都不能被综合分数隐藏。

## 数据位置

项目默认保存在当前浏览器。P2 数据结构版本为 v3，旧 v1/v2 项目会在读取或导入时迁移；证据工作区和执行工作区均保留。
