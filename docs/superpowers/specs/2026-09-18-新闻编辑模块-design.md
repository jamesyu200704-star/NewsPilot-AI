# 新闻编辑模块设计

## 目标

把现有“新闻编辑”入口改成三个真正并列、边界清楚的任务：语言润色、结构修改、新闻评论。用户只需选择任务并粘贴已有稿件，系统不得依靠搜索补写新闻事实。

## 功能边界

### 语言润色

- 输入：已有新闻稿、消息稿或采访整理稿。
- 处理：删除重复和赘词，修正病句、口语和指代不清，优化标题与新闻书面表达。
- 输出：润色后的完整稿件、简短编辑说明、原稿内部需要用户确认的问题。
- 限制：不得新增、删除或换算人名、机构、时间、数字、引语和因果关系。

### 结构修改

- 输入：事实基本完整但组织混乱的稿件。
- 处理：重写标题和导语，按新闻价值调整段落顺序，合并重复段落；根据材料选择倒金字塔、时间线或人物叙事。
- 输出：结构调整后的完整稿件、采用的结构及调整说明、材料缺口。
- 限制：只移动、压缩和改写已有材料，缺失的事实只能提示，不能补写。

### 新闻评论

- 输入：已有新闻稿或事实材料。
- 处理：从材料中提取评论对象，形成明确中心观点、论据、回应和结论。
- 输出：独立的评论标题和完整评论、观点说明、材料中无法支持的判断。
- 限制：事实与观点必须分开，不把推测冒充事实，不模拟不存在的采访和引语。

## 交互

新闻编辑页面保留三个并列按钮。切换按钮时，同步更新任务说明、输入框标签、占位文案和提交按钮。结果页继续显示完整成稿、编辑说明，以及确有必要时才显示的“需要确认的事实”。

## 验收

1. 三种任务的提示词、输入说明和提交动作明显不同。
2. 每种任务都返回完整可使用成稿，而不是修改建议列表。
3. 语言润色继续通过已有事实保护测试。
4. UI 回归测试和生产构建通过。
