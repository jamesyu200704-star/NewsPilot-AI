Git 历史中的凭据模式命中均来自 README 的空值或示例占位符，不需要撤销或轮换。真实研究参与者、研究场次和盲评结果均保持为 0。

## 已修复发现

### SEC-001：生成型测试目录忽略不完整

- 严重程度：Low
- 位置：`.gitignore:4-7`
- 证据：`coverage/` 已被忽略，但 `.vite/`、`playwright-report/` 和 `test-results/` 原先没有显式规则。
- 影响：未来运行工具后，缓存或测试产物可能被误加入发布提交。
- 修复：补充三个目录的忽略规则。
- 缓解：发布前继续使用显式路径暂存，禁止 `git add .` 与 `git add -A`。
- 误报说明：当前未跟踪文件中没有这些产物；本项是预防性修复。

## Critical / High

无开放发现。

## 已验证的安全控制

### SEC-002：客户端与配置密钥边界

- 严重程度：通过
- 位置：`.env.example:40,51`、`.gitignore:9-14`
- 证据：`BRAVE_SEARCH_API_KEY` 与 `OPENAI_API_KEY` 保持空值；`.env`、`.env.*` 与 `searxng/settings.yml` 被忽略，只有 `.env.example` 可跟踪。
- 结论：未把服务端 Secret 暴露为 `VITE_` 变量。

### SEC-003：React 注入与第三方脚本

- 严重程度：通过
- 位置：`src/`、`index.html`
- 证据：未使用 `dangerouslySetInnerHTML`、`innerHTML`、`document.write`、`eval`、字符串事件处理器、动态第三方脚本或不安全 `postMessage`。
- 结论：外部与用户文本继续通过 React 默认转义渲染。

### SEC-004：Express 输入与错误边界

- 严重程度：通过
- 位置：`server/app.ts:20,31-32,37-52,63-88`
- 证据：JSON 请求体限制为 32 KiB；禁用 `x-powered-by`；错误响应不返回堆栈、请求正文或上游错误；API 默认 `no-store` 与 `nosniff`。
- 结论：未发现错误信息泄密或无限 JSON 请求体。

### SEC-005：网页抓取 SSRF 防护

- 严重程度：通过
- 位置：`server/sources/SourceFetcher.ts:117-133,136-157,166-194`
- 证据：仅允许 HTTP(S)，禁止 URL 账号信息、本机、内网与元数据地址；DNS 解析后校验 IP；每次重定向重新校验；限制响应大小、内容类型、超时与跳转次数。
- 结论：未发现可直接访问 localhost、私网或云元数据的抓取路径。

### SEC-006：公开 Vercel 边界

- 严重程度：通过
- 位置：`vercel.json:12-29`、`src/services/研究模式.ts:1-6`、`src/App.tsx:248,401-440`
- 证据：公开响应设置 CSP、Permissions Policy、Referrer Policy、nosniff 与防嵌套头；研究事件只有在 `VITE_RESEARCH_MODE=true` 时才写入当前浏览器。
- 结论：公开构建使用 Mock / Manual 能力时不请求本机模型、搜索或转写端口，也不默认记录研究事件。

## 隐私与公开数据审计

- 三套 `examples/` 与 `qa/fixtures/` 均带 `fixtureMetadata.synthetic: true` 和“虚构教学数据”声明。
- `research/templates/` 与 `用户测试/` 只包含空模板或模拟字段，不包含真实参与者记录。
- `research/results/` 与 `qa/results/private/` 已被忽略。
- 当前候选文件不存在音频、视频、字幕、录音、私人联系方式或真实课程作业附件。
- 普通导出与研究事件的脱敏规则由 P2/P3 自动测试覆盖。

## 发布结论

在完整测试、依赖审计、GitHub Actions 和线上冒烟测试继续通过的前提下，当前候选版本可以作为公开 Beta 发布；不能把该结论解释为真实用户验证或正式稳定版认证。
