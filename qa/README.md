# P2 人工验收中心

这里把 P2 从“自动测试通过”推进到可重复的端到端人工验收。三个 `fixtures/` 文件都是可导入的空白起点，且只含虚构教学数据。

自动化测试能够证明：数据结构、规则、迁移、隐私过滤和导出逻辑按代码预期运行。它不能证明：学生理解流程、采访对象现实可达、中文 Word 视觉排版适合提交，或产品优于通用模型。

## 状态规则

只允许 `not_tested`、`passed`、`failed`、`blocked`、`needs_review`。没有实际执行、观察和证据时必须保持 `not_tested`，不得依据单元测试自动通过。

执行顺序：阅读 `P2_ACCEPTANCE_PLAN.md`，导入一个夹具，按主清单完成流程，再分别执行隐私、导出和移动端清单。截图只能保存脱敏界面；不得把真实采访、联系方式、逐字稿或私人笔记提交到仓库。

当前仓库不包含真实用户验收结果。Codex 或开发者的浏览器辅助验收只能算产品 QA，不能计入真实用户研究。

本轮开发者 QA 的逐项证据和限制记录在 `验收记录.json`。它不会把自动化、模拟采访或浏览器操作标记为真实学生反馈。
